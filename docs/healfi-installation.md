# Healfi рядом с AAPS

Healfi — отдельный вариант `healfi` этой ветки, с названием **Healfi** и пакетом
`app.healfi.androidaps`. Исходный вариант `full` остаётся AAPS с пакетом
`info.nightscout.androidaps`. Разные идентификаторы позволяют установить оба
приложения на один телефон; совпадение или различие их ключей подписи этому не
мешает. Обновления самой Healfi должны использовать её прежний ключ.

## Установка и данные

Тестовый APK собирается командой `:app:assembleHealfiDebug`, подписанный кандидат
Actions — вариантом `healfiRelease`. Удалять или заменять работающую AAPS не нужно.
Debug и Release могут быть подписаны разными ключами; в таком случае Release не
обновит установленную debug Healfi. Для постоянной установки выбирайте подписанный
кандидат Actions; debug предназначен для отдельного просмотра и проверки интерфейса.
При первой установке у Healfi собственные настройки и база; она не получает
суточный базальный профиль, IC/ISF, IOB, историю лечения или настройки радиомоста
из существующей AAPS автоматически. Имя базы `androidaps.db` может совпадать:
Android хранит её отдельно для каждого пакета.

В готовом APK проверяются название, пакет, уникальные разрешения и authorities
провайдеров. Разрешение Wear и маршрут его данных отделены от старой AAPS.
Закрытие уведомления адресуется своему пакету. Каталог результатов —
`Documents/Healfi/results`. Основной каталог экспорта выбирается пользователем
через системный SAF; общий каталог остаётся общим только при явном выборе.

Полный импорт настроек AAPS может сразу включить Medtronic, SMS, автоматизации и
прежние облачные назначения. Для первого просмотра интерфейса используйте
виртуальную помпу и отдельные тестовые настройки. Сохраняйте штатный экспорт
рабочего профиля, историю и оригинальный APK. Не копируйте одни коэффициенты еды
без полного профиля и истории активного инсулина для перехода на лечение.
Импорт настроек не переносит базу истории лечения и не гарантирует восстановление
IOB/COB: экспорт настроек и история лечения — разные данные.

**Только одно приложение должно управлять настоящей помпой.** Разные пакеты не
блокируют два одновременных контура и не обеспечивают эксклюзивный доступ к
OrangePro/RileyLink. Импорт рабочего экспорта и подключение к радиомосту не
являются пассивной проверкой: штатный драйвер способен синхронизировать часы и
базальный профиль. Не включайте второй closed loop рядом с работающим первым.
Эта сборка остаётся экспериментальной; программные проверки не подтверждают
физическую доставку или клиническую безопасность.

## Сенсор и дополнительные интеграции

В конфигураторе Healfi выберите **xDrip+ BG** источником глюкозы и оставьте
виртуальную помпу, пока OrangePro обслуживает работающая AAPS. В xDrip включите
локальную передачу данных. Если задан конкретный пакет получателя, добавьте Healfi,
сохранив работающую AAPS: `info.nightscout.androidaps app.healfi.androidaps`.
Текущая upstream xDrip разделяет получателей пробелом; названия настройки зависят
от версии на телефоне. При пустом поле получателя общий broadcast обычно уже
доступен обеим программам. Сверяйте время, единицы и свежесть новых показаний.

Разрешения Healfi и ограничения фоновой работы отдельные: предоставьте необходимые
разрешения новой программе и разрешите её работу в фоне в настройках OnePlus.
Они не наследуются от AAPS. Подключение Healfi к радиомосту для проверки приёма
глюкозы не требуется.

Healfi не использует Firebase-проект исходной AAPS: облачная телеметрия и Remote
Config отключены до отдельной регистрации. Локальные диагностические журналы
сохраняются. Поиск точки на карте без ключа недоступен, координаты вводятся
вручную. Фиксированные OAuth callbacks Open Humans и Tidepool удалены у Healfi,
чтобы не перехватывать авторизацию AAPS; эти интеграции требуют отдельной
регистрации. Старые AAPSClient не пересылают Wear datasets в Healfi. Приложение
часов имеет вариант Healfi, но для Data Layer нужны совпадающие пакет и подпись
телефона и часов; физическая работа часов не проверена.

Облачные назначения не изолируются только переименованием Android-пакета.
Не выбирайте общий путь экспорта или одновременно два локальных OAuth-сервера
без проверки настроек обоих приложений.
